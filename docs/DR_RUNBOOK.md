# 备份与容灾服务 灾难恢复手册（DR_RUNBOOK）

> 服务：`sm-backup-dr` ｜ 端口 8019 ｜ 数据库 `sm_backup_dr`

## 1. 数据库备份恢复步骤
1. 确认备份存在：`backupctl list --service sm-backup-dr`。
2. 在隔离库恢复最近全量备份：`backupctl restore --full <backup-id> --to <临时库>`。
3. 重放 WAL 至故障点（PITR），执行完整性校验。
4. 将恢复库地址切至服务配置并验证。

## 2. 服务降级方案
- 非核心接口（如统计、报表）可临时关闭，优先保障读写主链路。
- 数据库不可用时，返回降级提示页，写入队列暂存待恢复后回放。
- 降级开关通过配置热更新或 Feature Flag 控制。

## 3. 跨可用区/跨区域切换
1. 确认目标可用区/区域有同版本副本与数据副本。
2. 更新 Ingress/DNS 指向目标区域，ArgoCD 切换目标集群 Application。
3. 按"健康检查 → 核心接口冒烟 → 业务验证"顺序放量。
4. 原区域恢复后作为新备，避免双活写入冲突。

## 4. 演练频率与记录
- 每月一次恢复校验，每季度一次完整容灾演练。
- 每次演练记录：时间、执行人、RTO/RPO、问题项与闭环情况，归档至运维工单系统。

## 5. 备份恢复演练专项步骤（本服务为 DR 责任方，须最详细执行）

### 5.1 演练目标与频率
- 目标：验证 `sm_backup_dr` 及对象存储备份可在 1 小时内完成恢复，RPO ≤ 15 分钟，RTO ≤ 1 小时。
- 频率：每季度一次全量恢复演练，每月一次恢复校验（不实际切换生产）。

### 5.2 演练前准备
1. 在隔离环境（staging 或临时命名空间）拉起一套与生产同版本的 PostgreSQL。
2. 确认备份清单：全量备份（每周）+ WAL 归档（持续），异地副本存在且校验和一致。
3. 通知相关方并登记演练单号，明确不影响生产流量。

### 5.3 数据库恢复步骤
1. 列出可用备份：`backupctl list --service sm-backup-dr`。
2. 选取最近一个全量备份恢复到临时库：`backupctl restore --full <backup-id> --to pg-restore-check`。
3. 按时间点重放 WAL 至目标时刻（PITR）：`backupctl replay-wal --until "2026-xx-xx HH:MM:SS"`。
4. 执行完整性校验：`pg_checksums -D <datadir>`，并核对关键表行数与校验和。
5. 校验应用可连接：将临时库地址填入 staging 环境配置，跑通核心读路径。

### 5.4 对象存储/文件恢复
1. 从异地副本拉取最新快照，比对 manifest 校验和。
2. 恢复到隔离桶，抽样下载 10 个对象验证可正常读取。
3. 确认生命周期/分片临时区不影响生产数据。

### 5.5 容灾切换（演练态）
1. 在 DNS/Ingress 层将演练流量指向恢复环境。
2. 验证健康检查、接口冒烟、登录鉴权正常。
3. 记录切换耗时，计算实际 RTO/RPO 并与目标对比。

### 5.6 回退与复盘
1. 演练结束后切回生产，清理临时库与临时桶。
2. 输出演练报告：成功/失败项、实际 RTO/RPO、发现的问题与改进项。
3. 未通过项须在 2 周内闭环，并更新本 Runbook。
